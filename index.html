The problem

Anything encrypted today can be copied today and opened later.

Almost every bank, identity and health system protects its data with RSA or elliptic-curve encryption. A large quantum computer breaks both. Records that have to stay private for decades are exposed the moment they are recorded.

Today

Recorded

Encrypted traffic and backups are copied quietly. Storage is cheap, so attackers keep everything.

The next decade

Stored

The data waits. Identity numbers, medical history and signed contracts stay sensitive long after they are sent.

When quantum arrives

Opened

A cryptographically relevant quantum computer decrypts the archive. Whatever was not moved to new encryption is readable.

Product

From a folder of code to a migration plan.

Point Aegis at a repository, a container image or a server. It works through five steps and shows its reasoning at each one.

Step 1 · Discover

Find every piece of cryptography.

Aegis reads code the way a compiler does, so a comment that mentions RSA is ignored and a renamed import is still caught.

  • Python, Java, JavaScript, C and Go
  • Compiled binaries and container images
  • Certificates, keystores and Kubernetes secrets
  • nginx, HAProxy, SSH, OpenSSL and cloud key settings
  • Library versions with known weaknesses
Step 2 · Link

Follow the data to the key.

Aegis follows each sensitive value through the code until it reaches a crypto call, and shows every hop. Without a real path, there is no link.

  • Identity numbers checked with the Aadhaar checksum
  • PAN, IFSC and UPI formats recognised
  • Confidence shown for every link
Step 3 · Assess

Put a probability on every key.

How long the data must stay secret, plus how long migration takes, against when a quantum computer is likely to exist. The result is a chance, not a guess.

  • Arrival curve from a 26-expert survey
  • Elliptic-curve keys dated earlier than RSA
  • Your own criticality and exposure rules
Step 4 · Replace

Get the right fix, tested.

Encryption keys get ML-KEM, signing keys get ML-DSA or SLH-DSA, servers get hybrid key exchange. For common cases Aegis writes the patch and proves it.

  • Key and signature sizes, and the extra handshake bytes
  • Which browsers and clients already support it
  • Tests run before and after, on a copy
Step 5 · Prove

Hand over evidence, not a slide.

Every finding exports to the formats auditors and engineering teams already use, and each scan can be compared with the last.

  • Cryptography Bill of Materials (CycloneDX 1.6)
  • SARIF for GitHub and GitLab code scanning
  • Phased plan and a one-page board report

When does today's encryption stop working?

Nobody knows the exact year. So Aegis uses what experts actually said, and turns it into a probability for every key you run.

Source: Global Risk Institute, Quantum Threat Timeline Report 2025 (Mosca and Piani), 26 experts. Between 28% and 49% within 10 years and between 51% and 70% within 15 years. Aegis fits a smooth curve through the published ranges; "Earlier", "Middle" and "Later" use the high end, the middle and the low end.

The rule behind it

If the secret outlives the encryption, it is already at risk.

X+Y>Z
X · how long it must stay secret

An identity number is for life. A session token is for minutes. Aegis infers this from the data it traces.

Y · how long the move takes

A library swap is quick. A certificate authority, a firmware image or a partner integration takes years.

Z · when quantum arrives

Not one year, but the curve above. Aegis reports the chance that Z comes first.

Which falls first

Smaller keys are not always weaker, and elliptic curves fall first.

Breaking a key takes a certain number of error-corrected qubits. Elliptic-curve keys need fewer than RSA, so Aegis dates them about a year and a half earlier.

Logical-qubit counts: Häner, Roetteler and Svore 2017 (RSA, 2n+2); Roetteler et al. 2017 (elliptic curves). The spacing assumes usable qubits double every two years, which can be changed in the app.

Questions

Before you run it.

Does any of my code or data leave the machine?

No. Aegis has no telemetry and makes no network calls during a scan. The only network feature is the optional live server check, and it only contacts servers you type in.

Is the quantum year a prediction?

No. It is a smooth curve fitted to a published survey of 26 experts, shown as a probability. You can choose an earlier or later reading, or enter your own years, and every score updates.

How big a codebase can it handle?

We scanned Kubernetes, 31,296 files, in 46 seconds on one machine with 190 MB of memory. A second scan of the same code took 7 seconds, because only changed files are read again.

Will it change my code?

Only a copy, and only when you ask. Aegis writes the patch to a separate folder, runs your own tests before and after, and scans the copy again so you can see the result.

What is a CBOM?

A Cryptography Bill of Materials: a standard list of every algorithm, key, certificate and protocol in a system, in the CycloneDX format that auditors and security tools read.

Which languages and files does it understand?

Python in depth, including data flow, and Java, JavaScript, C and Go at the API level. Binaries, certificates, keystores, container images and server settings are read whatever language the system is written in.

Is the post-quantum code production-ready?

The automatic patch uses a reference implementation of ML-KEM so it runs anywhere. For production, the same standard is available in OpenSSL 3.5 and liboqs, and Aegis recommends those.
